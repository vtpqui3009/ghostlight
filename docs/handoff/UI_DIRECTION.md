# Ghostlight UI direction — Codex orchestration brief

This is original product/QA direction for the native Kiro author, not an implementation or Kiro evidence. Implement the reviewed requirements/design; make reasonable coherent design choices and deliver working behavior.

Build a polished Halloween theatre prop-planning desk. Use a distinctive editorial composition: warm parchment surfaces, midnight plum/charcoal navigation, restrained pumpkin and spectral mint accents, serif display headings with readable system sans text, subtle theatre/stage motifs drawn in CSS or original inline SVG. No external fonts/images/services are necessary. Give the stage and timeline room; avoid a wall of identical metric cards. At desktop, use a stage/timeline workspace with an action inspector; on narrow screens, stack useful sections with no horizontal dependency. Create a complete light/dark contrast hierarchy, visible keyboard focus, generous controls, thoughtful empty/error states, and a static reduced-motion equivalent.

The app checks a synthetic planned-state model. Label this clearly without claiming live tracking, real-user validation, or automatic stage detection. Keep implementation/vendor/internal QA details out of ordinary product flows.

Required working paths:

- Offer owned synthetic demos: valid control, missing handoff, consumed reuse with a different replacement ID, wrong physical duplicate, reordered cues/actions, and unknown initial state. Show descriptive labels and what the chosen demonstration is meant to expose.
- Replay selected action with authored REQUIRED ghost and computed BEFORE solid state visibly distinct through labels, physical IDs and text/icons, not only color or opacity. Show AFTER separately. Both zone and holder must be legible, including same-zone wrong-holder mismatches, absent/consumed/unknown states and crowded props.
- Timeline shows cue/action order, applied/rejected/uncertain states, issue messages and a causal link to the relevant earlier action or initial declaration. Prev/next/play/pause and reset cursor work; resetting playback is distinct from physical reset instructions. Editing pauses playback and recomputes derived data without stale selection.
- Edit scene title/description, zones, holders, physical prop instances and initial state, cues and all six action kinds. Preserve stable IDs on rename. Requirements remain independently authored; never repair them by copying computed state. Provide keyboard reorder buttons for cues and actions, add/delete controls, reference-aware blocking errors, validation next to fields and recoverable form drafts.
- Import/export validated versioned JSON. Bad JSON/version/size/reference input must retain current work and explain recovery. Export must preserve IDs/order/requirements. Render all imported labels as text. Include a useful empty scene path within the parser's minimum-zone contract.
- Recoverable local persistence: save only validated scene data; handle denied reads/writes and quota errors honestly; corrupt or unsupported saved content must not silently destroy work or claim success. Offer explicit retry/export/reset recovery choices as appropriate. Local computation after assets load is supported; do not claim guaranteed cold offline reopening.
- Preset, runner and physical reset reports use the domain report helpers. Runner retains rejected steps as rejected requirements; reset uses new IDs for consumed replacements and removal instructions for initially absent instances introduced into the show. Include print-friendly views with text warnings and stable ordering.

Keep components reasonably scoped and typed. Do not put the entire implementation in a huge untestable component. Actual accessibility matters: semantic landmarks/headings, associated labels/errors, meaningful control names, logical focus, focus restoration for dialogs, keyboard reachability, restrained announcements, no flashing/jump scares. Browser QA must exercise the real edit/replay/import/export/recovery workflow at desktop and 375/320px, 200%/400% reflow, reduced motion and print.

Use the installed Chromium at /usr/bin/chromium for Playwright if browser tests are added; do not download another browser unnecessarily. npm cache remains /tmp/ghostlight-npm-cache. The primary writer is Kiro; Codex reviews and runs independent QA. No deployment, paid assets/services, billing changes, external tracking, raw auth data or proprietary ClaudeKit content.

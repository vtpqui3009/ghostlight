## End-to-end oracles — all NOT RUN

1. **Valid replay and cursor reset.** Load the owned valid-control scene. Step through collect → transfer → carry → place. Each selected action shows its independently authored REQUIRED position against modeled BEFORE position with both zone and holder plus the physical ID; AFTER is separately labeled. Expect four applied steps and no issues, with hand-calculated final resting position. Play/pause/previous/next remain usable. Resetting the cursor returns to the first view without rewriting the scene or falsely claiming physical props were reset.

2. **Missing handoff and causal navigation.** Load the missing-handoff scene. At B's carry, expect rejection, REQUIRED holder B and BEFORE/AFTER holder A even when zones match. Follow the cause to the earlier successful collect on this same physical ID; return to the rejected step. The requirement remains B throughout. For unknown-start and malformed-action variants, distinguish initial-state uncertainty from action-shape error: only the initial-state case has an initial declaration link, and no invented position or spurious earlier action appears.

3. **Repair, reorder, and reference edits.** Add the missing transfer with an explicitly authored matching source and B destination, preserving unrelated action IDs. Rerun: the repaired carry passes and warnings/stage/reports agree. During playback, edit or reorder a cue/action: playback pauses or predictably updates, and selection never points at stale frames. Reverse a known place/collect pair: collect fails against the actual earlier state; restore order and it passes. Rename a referenced entity without changing its ID. Attempt deletion while referenced: block with the actual reference list and retain the scene/draft.

4. **Physical identity and terminal consumption.** In the consumed-reuse scene, consume A, replenish predeclared absent B, then attempt to reuse A: A stays consumed and the reuse remains rejected. Retarget the authored action to B with an explicit valid source: B can pass without reviving A. In the duplicate scene, equal display names must not merge A/B, redirect a requirement, or conceal the chosen ID in the inspector and reports.

5. **JSON round trip and failed-import preservation.** Export an edited scene; capture its actual download and parse it independently. Reopen it and compare version, IDs, cue/action order, sources/destinations, and notes. Attempt malformed JSON, unsupported version, duplicate/missing references, forbidden IDs, and above-200,000-byte multibyte JSON: show a bounded useful error while preserving current work and draft. Import HTML-like labels and an allowed `toString` ID: render labels as text, execute nothing, and preserve identity. Start-empty produces a valid minimum-zone scene with actionable empty UI.

6. **Recoverable persistence failures.** In isolated browser contexts, inject `Storage.prototype.getItem`/`setItem` failures before page code loads (SecurityError and QuotaExceededError), and separately seed corrupt or unsupported saved data under the actual application key. The app still opens with a recovery explanation; edits remain in memory, export remains possible, and failed saves never show success. Corrupt saved bytes are not silently replaced. Restore storage and use explicit retry/recovery: the valid scene saves and reloads with the same authored requirements. Do not use the normal profile for these fault injections.

7. **Keyboard, focus, and readable alternatives.** Complete load → select rejection → follow cause → open editor → invalid field → correct field → save → export using keyboard alone. Check visible focus, meaningful names, label/error associations, sensible tab order, dialog focus containment/restoration where applicable, and keyboard cue/action reorder. Equivalent text/list state includes physical ID, status, zone, holder, applied/rejected result, and cause; color, opacity, hover, and animation are never the sole carrier. Result announcements update usefully without narrating every autoplay animation frame.

8. **Responsive layout and reflow.** Inspect desktop plus 375px and 320px viewports with long labels and crowded props. Essential controls, source/destination fields, explanations and report actions remain visible or reachable without clipped content or a horizontal navigation dependency. Check 200% and 400% zoom/reflow separately; a screenshot at smaller width alone is not evidence of actual browser zoom. Record the exact method and any unsupported check. The stage/timeline still have a usable reading order and both REQUIRED/BEFORE comparisons remain understandable.

9. **Reduced motion and stable playback.** Set `reducedMotion: 'reduce'` before navigation and verify the actual media query matches. The complete state, rejection and cause information remains visible in a static equivalent; no motion/flicker is required to locate a prop or error. Step/pause/reset and editing remain functional. Compare scene exports before/after playback to prove animation did not mutate authored requirements.

10. **Practical reports and print.** For valid, missing-handoff, consumed/replacement, introduced-absent and unknown-start scenes, inspect preset/runner/reset in screen and print media. Preset matches declared initial state; runner preserves ordered requirements and flags rejected operations as rejected; reset asks to replace consumed IDs, removes introduced initially absent instances, and marks unknown locations uncertain. Print includes title, physical IDs, stable ordering and warning text without requiring background colors. Check long reports for clipped rows/page breaks; produce a temporary PDF only as internal verification and report any physical-printer check as unperformed.

Pair assertions with visual/keyboard inspection; a successful build or existing spec is not browser evidence. Keep failed cases and Kiro-authored fixes linked.

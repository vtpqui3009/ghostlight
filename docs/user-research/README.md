# User research kit

Potential Impact is 20% of the score and asks "**would someone actually use this?**". Right now the
answer is backed by nothing. Two sessions with experienced stage managers or ASMs would change that
more than any feature will.

This kit is written so the session can be run without preparing anything else.

| File | Use |
|---|---|
| [`consent.md`](consent.md) | Read or send before the session. Covers recording, anonymisation and withdrawal. |
| [`interview-guide.md`](interview-guide.md) | The session itself, in order, with timings. |
| [`findings-template.md`](findings-template.md) | Where the results go, including the ones that hurt. |

## The rules that make the result worth having

- **Run the sessions separately.** Two people in one room converge on one opinion.
- **Do not demo first.** Ask them to explain a real sequence and how they handle it today *before*
  Ghostlight is mentioned. That baseline is the only thing their reaction can be measured against.
- **Do not point at the planted fault.** Give them the scenario and let them find it or not. "Did
  you see how it caught that?" produces a yes that means nothing.
- **Separate instruction time from task time.** Note them as two numbers. A tool that takes ten
  minutes to explain and two to use is a different product from one that takes two and ten.
- **Write down what they say, in their words.** Paraphrase loses the thing that was useful.
- **Record the counter-evidence first.** If someone says the data entry is not worth it, that is
  the single most valuable sentence in the session and it goes at the top of the findings.
- **Praise is not evidence.** Neither is "I could see myself using this". The question that counts
  is whether they would use the output for a specific real job this season, and what would stop
  them.

## Anonymising a real run sheet

If a participant shares a real sequence, before it touches this repository or the demo:

1. Remove performer and crew names, replace with roles — "Actor A", "ASM stage right".
2. Remove the production name, venue, company and dates.
3. Remove anything about an individual's circumstances, access needs or employment.
4. Keep an unmodified private copy and a written list of every change, so a fault that was
   introduced during anonymisation is never mistaken for one that was in the original.
5. Ask the participant to confirm the anonymised version is safe to use **before** it is used.

If in doubt, build an equivalent synthetic scene with the same shape instead. The six bundled demo
scenes were made that way.

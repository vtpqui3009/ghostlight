# K8 — verify the hook actually triggers

**Goal:** turn a NOT VERIFIED line in the evidence file into an observation, or into an honest
negative result.

## Why this matters

`KIRO_SESSION_EVIDENCE.md` says, from 2026-10-31:

> Native automatic hook discovery/trigger execution remains **NOT VERIFIED** and must be
> demonstrated during T2. A manually invoked script is not evidence of a native trigger.

`.kiro/hooks/domain-typecheck.json` declares a `PostFileSave` hook matching
`(^|/)src/domain/.*\.tsx?$`, running `bash .kiro/hooks/typecheck-domain.sh` with a 30 second
timeout. The JSON parses, the regex matches the right paths, and the script's syntax is valid —
all checked. What has never been seen is Kiro running it by itself after a save.

This is cheap and it is the difference between "we configured a hook" and "we used one", which is
exactly what the Technological Implementation criterion asks about.

## What to do, in Kiro

1. Open the project in a native Kiro session.
2. Save a file under `src/domain/` — a whitespace-only change is enough; revert it afterwards.
3. Observe whether the hook fires without being asked. Record what appeared, verbatim, in the
   session.
4. Do the same for a file **outside** `src/domain/` and confirm it does **not** fire, so the match
   is real rather than the hook running on every save.

## Record either outcome

- If it fires: append the observation to `KIRO_SESSION_EVIDENCE.md` with the date, what was saved
  and what the hook printed, and replace the NOT VERIFIED line.
- If it does not fire: say so just as plainly, with what you tried. A negative result honestly
  recorded is worth more than a claim, and it is still evidence of real use.

Do not simulate a trigger by invoking the script yourself and describing it as a trigger. That is
the specific thing the existing note warns against.

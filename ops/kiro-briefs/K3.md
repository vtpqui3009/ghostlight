# K3 — the list equivalent and reduced motion

**Goal:** the same information as the stage diagram, without the diagram.

**Surface:** Kiro CLI. Do this **before K7**: both touch the first-screen and stage regions.

**Re-checked against the code on 2026-11-10:** `src/ui/StageView.tsx` still has no list or table
equivalent and nothing in `src/` reads `prefers-reduced-motion` from script (only a CSS
`@media (prefers-reduced-motion: reduce)` block in `src/styles.css`). K4 has since made the cause a
button in this same file, so keep that control working. If K10 has run first, the diagram may look
different; keep the same REQUIRED/BEFORE labels either way.

## What already exists — read this before planning

Ghost versus solid is **already implemented**. `src/ui/StageView.tsx` builds entries typed
`'required' | 'planned' | 'match' | 'mismatch' | 'other'` and labels them in words:
`REQUIRED: Sealed Letter (letter-A)` and `BEFORE: Sealed Letter (letter-A)`. So the diagram and its
text labels are done.

What is missing is the **equivalent**: a plain ordered list or table carrying the same facts, for
reduced motion, for a narrow screen, for print, and for anyone reading linearly. The project's
requirement 6 asks for "readable alternatives, reduced motion"; the research plan asks for a
"bản danh sách/bản in tương đương khi giảm chuyển động".

`@media print` already exists in `src/styles.css` around line 741, so print styling is partly there.

## Paste this into Kiro

```text
Ghostlight's stage view already shows required-versus-planned state with word
labels (REQUIRED / BEFORE) in src/ui/StageView.tsx. Add the equivalent reading of
the same state as an ordered list or table, carrying the same facts: every
instance by id and name, where the selected action requires it, where the plan
puts it, and whether those agree.

- Let the reader choose between the diagram and the list, and remember the
  choice for the session.
- Default to the list when the browser reports prefers-reduced-motion: reduce.
- The list must stand alone: someone who never sees the diagram should be able to
  read the same mismatch from it, including which instance and which holder.
- It must print legibly; @media print already exists in src/styles.css.
- No horizontal overflow at 390px.

Do not duplicate the state calculation. Both views read the same derived data, so
they can never disagree.

Add tests at the level the project already tests the UI, then run npm run lint,
npm run typecheck, npm test and npm run build and report the real results.
```

## Acceptance

- With `prefers-reduced-motion: reduce` emulated, the list is what renders first.
- The list names the instance id, the required position and the planned position for the selected
  action, and says whether they agree.
- No horizontal overflow at 390 px — the harness checks this.
- Diagram and list are derived from the same data, not computed twice.
- The K4 cause button (jumps to the earlier action) still works from the list view.
- `npm run check` green with the real test count; `npm run test:e2e -- --strict` green and the
  axe baseline still empty. If Playwright is not installed, say NOT RUN and leave it to CI.

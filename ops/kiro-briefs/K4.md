# K4 — make the cause navigable

> **DONE 2026-11-10 — implemented by the reviewer, not Kiro.** Kept as the record. Do not run this
> again. See `ops/RUN_LOG.md` run 9.

**Goal:** let a finding take you to the earlier action that caused it, in one click or one key.

## What already exists — read this before planning

The cause is **already computed and already shown**. `src/ui/StageView.tsx` around line 112 renders:

```
Cause: Earlier action a1 in cue cue-1
```

or `Initial state of letter-A`. So the engine's causal trace works and the UI prints it. What is
missing is only that the text is inert: it names `a1` and `cue-1` by raw id and you cannot get there
from it.

This is a small change with a large payoff — it is the 1:00–1:45 beat of the demo script.

## Paste this into Kiro

```text
In Ghostlight, a finding already prints its cause in src/ui/StageView.tsx, as
"Earlier action a1 in cue cue-1" or "Initial state of letter-A". Make that cause
reachable instead of inert.

- When the cause is an earlier action, render it as a control that selects that
  action's frame in the timeline, the same selection the timeline itself makes.
  It must work with the keyboard and show a visible focus ring.
- Name it with words, not raw ids: the cue title and what the action does, the
  way the timeline writes it. Keep the id visible somewhere, since two identical
  props are told apart by id.
- When the cause is the initial state, take the reader to that instance's
  starting declaration in the editor, or say plainly that it is the recorded
  starting state if there is nowhere to go.
- After navigating, the selected action must be the earlier one, and its own
  required-versus-planned view must render.

Do not change the engine, the cause data or how causes are computed: a cause must
still never point at a later action. This is presentation only.

Add a test for the navigation at the level the project already tests the UI, then
run npm run lint, npm run typecheck, npm test and npm run build and report the
real results.
```

## Acceptance

- From a `source-mismatch` finding on the `Missing Handoff — Wrong Holder` demo, one activation
  selects the cue 1 action, with the keyboard as well as the mouse.
- The control is reachable by keyboard and has a visible focus indicator.
- No engine or domain change; causes still only point backwards.

## Must not change

`src/domain/**`, the shape of `Issue.cause`, or the rule that a cause is an earlier action or the
initial state.

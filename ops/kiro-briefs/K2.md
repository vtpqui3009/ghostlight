## REOPENED 2026-11-10 — the selected row the first scan could not see

**Goal:** give the selected timeline row a foreground that is readable on its own background, in
both colour schemes.

### Why this came back

K2 was closed on a scan that reported zero violations. That scan was wrong about the app, not
because axe was wrong, but because the harness never put the app into the state where this defect
exists: **nothing is painted mint until a timeline row is clicked**, and the original four scans
never clicked one. They also only ran the light scheme. Both gaps are now closed in
`tests/e2e/specs/accessibility.spec.mjs`, which is reviewer-authored.

With a failing row selected, measured by axe-core 4.14.0 on 2026-11-10:

| Scheme | Nodes | Worst measured ratio |
|---|---|---|
| light | **1** | 3.91:1 — `#5a5a5a` on `#7ed4ad` |
| dark | **6** | 1.91:1 — `#e8e5dc` on `#5eb88f` |

Recorded in `tests/e2e/axe-baseline.json` under `stage-view-selected` and
`stage-view-selected-dark`. `npm run test:e2e -- --strict` fails on exactly these two and nothing
else. A wider reviewer sweep over three demos, three views and both schemes found **19** nodes of
the same rule, **all of them on the stage view with a row selected**; the first screen, reports and
editor are clean in both schemes.

### The cause, and it is one line

`src/styles.css` around line 342:

```css
.action-item.selected {
  background: var(--mint);
  font-weight: 500;
}
```

It sets a background and no foreground. Everything inside the row keeps the colour it had against
parchment — `.action-secondary` is `--text-mid` (`#5a5a5a`), `.prop-id` and `.prop-position` the
same family — and in the dark scheme `--mint` becomes `#5eb88f` while the inherited text is
`#e8e5dc`, which is 1.91:1.

This is the **same class of bug K2 already fixed everywhere else**: a surface whose foreground was
not paired with it. The fix is the same shape — a role token pair, not a per-selector patch.

### What to do

Add a selected-row role token pair alongside the others in `:root` and in the
`prefers-color-scheme: dark` block, and have the row set both halves:

```css
.action-item.selected {
  background: var(--selected-bg);
  color: var(--selected-fg);
  font-weight: 500;
}
```

Then make the descendants that currently hard-code a dimmer colour inherit inside a selected row,
or give them their own `--selected-fg-muted` that is checked against `--selected-bg`. The nodes axe
names are `.action-label > .action-primary`, `.action-label > .action-secondary`, `.prop-id` and
`.prop-position`.

Pick the values by measuring, not by eye. Every pair must reach **4.5:1**, and say in the comment
what each measured, exactly as the existing token comments in `src/styles.css` already do.

### While you are in there — the thing that reads as wrong

A **rejected** step, when selected, sits on a mint-green fill. Green means "this one is fine"; the
row is the failing step. The status dot is the only thing saying otherwise. This is a correctness
problem in the visual language, not a nit, and it is the first thing a judge sees when they follow
the demo script.

The selected row should stay legible **and** keep its status legible. One defensible shape: keep the
selection cue neutral (a strong left border, a weight change, a focus-coloured outline) and let the
status colour stay the row's own, so selection and verdict no longer fight. Do not express
selection with a success colour.

That part overlaps **K10**, which owns the visual language. If you do K10 first, fold this in there
and say so; the contrast pairs still have to be measured either way.

| Screen | Rule | Nodes | Targets |
|---|---|---|---|
| first screen | `landmark-one-main` | 1 | `html` |
| first screen | `region` | 2 | `h2`, `.empty-state > p` |

## Three causes, not three hundred nodes

1. **`landmark-one-main` and `region` are one bug.** `src/App.tsx` renders `<main className="app-main">`
   only on the branch where a scene is loaded (around line 193). The empty-state branch (around line
   178) renders `<div className="empty-state">` with an `<h2>` and a `<p>` outside any landmark. The
   first screen a judge sees therefore has no `main`. Give the empty state the same `<main>` wrapper.

2. **`color-contrast` is a token problem, not 32 separate ones.** `button.small` (`src/styles.css`
   around line 184) only sets padding and font size, so the failing pair comes from the base button
   and `.secondary` colours against their background, and from `.small` text spans using
   `--text-mid` (`#5a5a5a`) or `--text-light` (`#888`) on `--parchment`. Fix the tokens so every
   instance passes; do not special-case the selectors axe happened to name. Check both the light
   palette and the `prefers-color-scheme: dark` block (around line 46) — axe scanned one of them.

3. **`label-content-name-mismatch` is two `aria-label` strings in `src/ui/Timeline.tsx`.**
   - The cue header's label is `` `Cue: ${cue.title}. ${cueFrames.length} actions. Click to …` `` while
     the visible text says `1 action` in the singular. The accessible name must contain the visible
     text; `actions` vs `action` breaks it.
   - The action row's label is `` `Action ${kind} on ${prop}. Status: ${status}` `` while the visible
     text also includes `ID: letter-A • source-mismatch`. The visible text is not part of the name.

   Prefer letting the visible text *be* the accessible name and adding only what is not on screen,
   rather than writing a parallel sentence that has to be kept in sync.

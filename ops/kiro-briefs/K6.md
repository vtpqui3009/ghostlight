# K6 — reports: the 390 px overflow and CSV export

**Goal:** make the reports usable on a phone and exportable as CSV.

## Measured evidence

`npm run test:e2e` fails one test today, and it is written down in `tests/e2e/known-failures.json`:

```
responsive — 390 px phone viewport > Reports view has no horizontal overflow with a scene loaded
Reports view overflows by 73px; widest offender <table class="report-table"> spills 73px
```

`src/ui/Reports.tsx` renders three `table.report-table` elements — preset, runner, reset. The first
screen, stage and editor are all clean at 390 px; only reports spills.

## What already exists

A print button calling `window.print()` is at the bottom of `src/ui/Reports.tsx`, and
`src/styles.css` has an `@media print` block. **CSV export does not exist anywhere** — nothing in
`src/` mentions it.

## Paste this into Kiro

```text
Two things in Ghostlight's reports.

1. Reports overflow a 390px viewport by 73px. src/ui/Reports.tsx renders three
   table.report-table elements -- preset, runner, reset. Make them readable at
   390px without the page scrolling sideways. A contained horizontal scroll on
   the table itself is acceptable if the table keeps a visible affordance and
   stays reachable by keyboard; collapsing to stacked rows on narrow screens is
   better if it keeps the columns legible. The other three views already pass, so
   match whatever they do rather than inventing a second approach.

2. Add CSV export for the reports. One file per report, or one file with a report
   column -- your choice, but say which in the UI. Every row must carry the
   physical instance id, not just the display name, because two identical props
   are told apart by id. Quote fields containing a comma, quote or newline, and
   guard against spreadsheet formula injection: a field starting with =, +, - or
   @ must not be executed when opened in a spreadsheet.

   The export is a file download from the browser. Nothing is uploaded anywhere.

Do not change what the reports contain or the order of their rows: ordering is
part of what makes a printed sheet trustworthy.

Add tests for the CSV escaping, including a field that starts with = and a field
containing a quote. Then run npm run lint, npm run typecheck, npm test and
npm run build and report the real results.
```

## Acceptance

- `npm run test:e2e` passes with no entry left in `known-failures.json` — **delete the entry when it
  passes**, or the harness fails the run on purpose, naming it.
- CSV downloads for each report, with instance ids present, correct quoting and formula injection
  neutralised.
- Report content and row order unchanged.

## Must not change

What the reports say, their row order, or the print stylesheet's behaviour.

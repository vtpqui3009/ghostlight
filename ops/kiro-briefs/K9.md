# K9 — dependency advisories

**Goal:** clear the critical and high advisories before the repository is public.

## Measured evidence

`npm audit` on 2026-11-10: **12 vulnerabilities — 9 moderate, 1 high, 2 critical**.
`npm audit --omit=dev`: **0**. Everything is build and test tooling; nothing ships to the browser.

| Severity | Package | Range |
|---|---|---|
| critical | `tinypool` | ≤2.1.1 — prototype pollution gadget to RCE in worker options |
| critical | `vitest` | ≤4.0.0-beta.19 — arbitrary file read and execution when the UI server listens |
| high | `vite` | ≤6.4.3 — path traversal in optimized-deps `.map` handling |

The repo is on `vite` 5.4.21 and `vitest` 1.6.1. Dependency modernisation has been open since
2026-10-31, when npm reported the selected ESLint version unsupported.

## Why this is Kiro's and not a reviewer bump

A `vite` and `vitest` major jump can break the 222 Kiro-authored tests and the build. That is
application work with a real chance of fallout, so it belongs to the author of those tests.

Do it **last**. A broken suite in the final week is worse than a dev-only advisory in a repository
whose README already states the position.

## Paste this into Kiro

```text
Update Ghostlight's build and test tooling to clear the critical and high npm
advisories: vitest (currently 1.6.1) and vite (currently 5.4.21), and tinypool
which comes in through vitest.

Move one package at a time and run the full suite after each step, so a failure
is attributable. Keep every test meaningful: if a test needs rewriting for a new
API, rewrite it so it still asserts the same behaviour -- do not delete it, relax
it or mark it skipped to get a green run.

Expect work in the vitest config and possibly in eslint and typescript-eslint,
which npm already reported as a version mismatch on 2026-10-31.

When finished, report npm audit and npm audit --omit=dev, plus npm run lint,
npm run typecheck, npm test and npm run build, with the real numbers. If an
advisory cannot be cleared without breaking something, stop and say which, rather
than forcing it.
```

## Acceptance

- `npm audit` reports no critical and no high advisories, or the remainder is explained in
  `QA_RESULTS.md` with a reason.
- `npm test` still reports 222 or more passing tests, none skipped.
- `npm run check` green; CI green.
